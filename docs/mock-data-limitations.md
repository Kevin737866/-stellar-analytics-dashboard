# Mock Data Limitations and Horizon Simulation Boundaries

This document provides a comprehensive inventory of the mock data generator (`indexer/src/mock-horizon.ts`) used when running with `STELLAR_MOCK=true`. It details the boundaries, unsupported features, and cryptographic discrepancies between the mock environment and a live Stellar Horizon node.

## 1. Overview and Architecture

The mock mode is designed to enable offline local development and deterministic unit testing without requiring network connectivity, Horizon rate limits, or friendbot funding.

When `STELLAR_MOCK=true` is set (or when `createMockHorizonServer()` is instantiated directly in tests), the indexer bypasses the official `@stellar/stellar-sdk` `Horizon.Server` network client and instead connects to an in-process, deterministic data generator.

```
STELLAR_MOCK=false:  Indexer  ──(HTTP/REST)──▶  Stellar Horizon (Testnet / Mainnet)
STELLAR_MOCK=true:   Indexer  ──(in-process)──▶  mock-horizon.ts (Synthetic Generator)
```

## 2. API Surface Coverage vs Gaps

The mock server only implements the specific subset of `Horizon.Server` methods invoked by `indexer/src/ingester.ts`:

### Supported Horizon Methods

- `server.ledgers().order('desc').limit(1).call()` — Fetches the latest synthetic ledger.
- `server.ledgers().ledger(sequence).call()` — Fetches a synthetic ledger by sequence number.
- `server.transactions().forLedger(sequence).call()` — Generates transactions for a ledger.
- `server.operations().forLedger(sequence).call()` — Generates operations for transactions in a ledger.

### Unimplemented Horizon Endpoints

The following live Horizon endpoints and features are **not supported** by the mock server:

- `/accounts` — Account balances, signers, trustlines, thresholds, and flags.
- `/assets` — Asset directory, supply metrics, and issuer flags.
- `/offers` and `/trades` — Orderbook, bid/ask depth, and trade history.
- `/claimable_balances` — Claimants, predicates, and claimable balance IDs.
- `/liquidity_pools` — Reserves, shares, fees, and pool participant accounting.
- `/effects` — Granular operation effects.
- `/fee_stats` — Dynamic fee percentiles and surge pricing stats.
- Streaming SSE (`.stream({ onmessage: ... })`) — Real-time event streaming is simulated via polling increments rather than server-sent events.
- Soroban RPC — Smart contract simulation, contract state queries, and transaction submission.

## 3. Cryptographic and Identity Limitations

### Synthetic Account IDs

Account IDs generated by the mock mode use the format:

```
GAAA + zero-padded seed (52 digits)
Example: GAAA0000000000000000000000000000000000000000000000000001
```

- **Checksum Invalidation**: These synthetic strings are formatted to match basic 56-character `G...` patterns, but **they do not possess valid CRC16 checksums**.
- Cryptographic checks using `StrKey.isValidEd25519PublicKey()` or `Keypair.fromPublicKey()` will intentionally reject mock account IDs.
- Ingestion and storage pipelines that perform strict StrKey checksum validation will reject mock accounts unless bypassed in test mode.

### Signatures and Keys

- Mock transactions contain empty signature lists (`signatures: []`).
- No private keys exist for mock accounts; transactions cannot be verified with `keypair.verify()`.

## 4. XDR Serialization Limitations

Live Horizon transactions and ledgers contain valid base64-encoded Stellar XDR (External Data Representation) structures. The mock generator provides placeholder strings instead:

| Field             | Mock Representation            | Live Horizon Equivalent                   |
| ----------------- | ------------------------------ | ----------------------------------------- |
| `header_xdr`      | `MOCK_LEDGER_XDR_<seq>`        | Base64-encoded `LedgerHeaderHistoryEntry` |
| `envelope_xdr`    | `MOCK_TX_ENVELOPE_XDR_<hash>`  | Base64-encoded `TransactionEnvelope`      |
| `result_xdr`      | `AAAAAAAAAGQ=` (constant stub) | Base64-encoded `TransactionResult`        |
| `result_meta_xdr` | `MOCK_META`                    | Base64-encoded `TransactionMeta`          |
| `fee_meta_xdr`    | `MOCK_FEE_META`                | Base64-encoded `LedgerEntryChanges`       |

Attempting to deserialize mock XDR strings using `xdr.TransactionEnvelope.fromXDR()` or `xdr.LedgerHeader.fromXDR()` will throw deserialization errors.

## 5. Supported vs Unsupported Operation Types

The mock generator cycles deterministically through a fixed array of 6 operation types:

### Supported Operation Types (6)

1. `payment`
2. `create_account`
3. `path_payment_strict_receive`
4. `manage_sell_offer`
5. `change_trust`
6. `account_merge`

### Unsupported Operation Types (17+)

The following Stellar operations are never produced by the mock generator:

- `path_payment_strict_send`
- `manage_buy_offer`
- `create_passive_sell_offer`
- `set_options`
- `allow_trust`
- `inflation`
- `manage_data`
- `bump_sequence`
- `claim_claimable_balance`
- `begin_sponsoring_future_reserves`
- `end_sponsoring_future_reserves`
- `revoke_sponsorship`
- `clawback`
- `clawback_claimable_balance`
- `set_trust_line_flags`
- `liquidity_pool_deposit`

- `invoke_host_function` (Soroban Smart Contract executions)
- `extend_footprint_ttl` / `restore_footprint`

## 6. Asset and Accounting Limitations

- **Asset Variety**: All generated `payment` and `path_payment_strict_receive` operations only use native `XLM`. Credit assets (`credit_alphanum4`, `credit_alphanum12`) are not automatically generated.
- **Fixed Supply Figures**: Total coins is fixed to `"100000000000.0000000"` and fee pool is fixed to `"1234.5678900"`.
- **No State Accumulation**: Account balances are not tracked or mutated across ledgers. Sending 100 XLM does not deduct from the source account or credit the destination account.
- **Synthetic Paging Tokens**: Paging tokens follow the schema `${sequence}-${txIndex}` or `${sequence}-${txIndex}-${opIndex}` instead of live Horizon 64-bit integers.

## 7. Environment Usage Matrix

| Use Case                               | Mock Mode (`STELLAR_MOCK=true`) | Live Network (Testnet / Mainnet) |
| -------------------------------------- | ------------------------------- | -------------------------------- |
| Frontend UI prototyping & styling      | ✅ Recommended                  | ⚠️ Slower & rate-limited         |
| Offline developer environment          | ✅ Fully supported              | ❌ Network required              |
| Ingestion pipeline unit tests          | ✅ Fast & deterministic         | ❌ Flaky & slow                  |
| Soroban smart contract analytics       | ❌ Unsupported                  | ✅ Required                      |
| Cryptographic signature verification   | ❌ Synthetic keys               | ✅ Required                      |
| Real transaction submission            | ❌ No network connection        | ✅ Required                      |
| Asset trustline & market analytics     | ❌ Native XLM only              | ✅ Required                      |
| Playwright E2E full-stack verification | ⚠️ Basic flow only              | ✅ Recommended                   |
